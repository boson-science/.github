# Security policy

Boson Science values responsible vulnerability research and coordinated
disclosure.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use the affected repository's **Security** tab and select **Report a
vulnerability**. If private vulnerability reporting is unavailable, follow the
private contact instructions in that repository's README or `SECURITY.md`.
Avoid sending exploit details through a public issue, discussion, or pull
request.

Include, when possible:

- the affected repository, version, commit, or deployment;
- the prerequisites and steps needed to reproduce the issue;
- the security impact and realistic attack scenario;
- a minimal proof of concept; and
- any suggested remediation or disclosure constraints.

## What to expect

Maintainers will acknowledge a report as soon as practical, validate its impact,
and coordinate remediation and disclosure with the reporter. Response and
release timing depends on severity, reproducibility, affected users, and the
complexity of a safe fix.

Good-faith research that avoids privacy violations, data destruction, service
disruption, persistence, lateral movement, and access beyond what is necessary
to demonstrate the issue is welcome.

## Supported versions

Each project documents its supported versions. Unless a repository states
otherwise, only the latest released version and the default development branch
should be assumed to receive security fixes.
