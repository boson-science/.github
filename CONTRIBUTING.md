# Contributing to Boson Science projects

Thank you for helping improve a Boson Science project.

## Before opening an issue

1. Read the repository README and existing documentation.
2. Search open and closed issues for an existing report or proposal.
3. Confirm that the topic belongs to this repository.
4. Do not report security vulnerabilities in a public issue; follow
   `SECURITY.md` instead.

## Proposing a change

For a small, well-understood correction, a pull request may be opened directly.
For a substantial feature, behavior change, new dependency, or public API
change, open a proposal first so maintainers can confirm the direction before
implementation work begins.

## Pull requests

A pull request should:

- have one clear purpose;
- explain the problem and the chosen solution;
- include tests proportional to the risk of the change;
- update documentation and examples when behavior changes;
- avoid unrelated formatting or refactoring;
- preserve license and attribution notices; and
- pass all required automated checks.

Maintainers may ask for a change to be split when independent concerns would be
easier to review and release separately.

## Licensing contributions

By contributing, you agree that your contribution may be distributed under the
license declared by the target repository. Do not submit code or other material
that you do not have the right to contribute. Identify third-party material and
its license in the pull request.

## Conduct

Participation is governed by `CODE_OF_CONDUCT.md`.
